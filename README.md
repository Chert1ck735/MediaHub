# СИГМА · MediaHub

**Платформа для мониторинга и анализа пабликов.**

СИГМА собирает публикации и комментарии пабликов в одном рабочем пространстве. Она помогает анализировать активность пабликов, находить значимые темы обсуждений, отслеживать реакцию аудитории и готовить контент на основе полученных данных.

Типичный сценарий: подключить паблики → собрать их публикации и комментарии → проанализировать комментарии с помощью LLM → изучить статистику и темы обсуждений → подготовить отчёт и контент для пабликов.

## Возможности

- **Сбор данных пабликов.** Импорт публикаций и комментариев из ВКонтакте, Одноклассников и Telegram, фоновые проверки обновлений. Доступность данных зависит от API и прав учётной записи.
- **Анализ комментариев пабликов.** Классификация по релевантности, тональности, типу сообщения, категории и подкатегории; выделение значимых сообщений и тем обсуждений.
- **География обсуждений.** Извлечение адресных кейсов из комментариев пабликов, геокодирование и отображение на карте. Для геокодирования в поставку входят справочники населённых пунктов и объектов Красноярского края.
- **Статистика и отчётность по пабликам.** Сводки по пабликам и периодам, динамика обсуждаемых тем, анализ ответов в комментариях и PDF-отчёты.
- **Контент для пабликов.** Генерация вариантов постов с помощью LLM, работа с событиями и календарём публикаций.
- **Командная работа с пабликами.** Организации, пользователи, приглашения, группы и разграничение прав доступа.

Классификация и геокодирование могут ошибаться: результаты предназначены для проверки и работы аналитика. Качество и скорость обработки зависят от модели и внешних сервисов.

## Быстрый запуск через Docker

Понадобятся Docker Engine и плагин Docker Compose v2. Команды выполняются из корня проекта. Модель LLM запускается отдельно и в Compose не входит.

### 1. Подготовьте настройки

```bash
cp .env.example .env.docker
cp frontend/.env.example frontend/.env
```

В `.env.docker` задайте:

```dotenv
APP_ENV=dev
DB_HOST=db
DB_PORT=5432
DB_NAME=media_project
DB_USER=postgres
DB_PASS=change_this_local_password
JWT_SECRET=replace_with_a_generated_secret
```

Замените пароль и сгенерируйте собственный `JWT_SECRET` длиной от 32 символов:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Для LLM укажите `LLM_PROVIDER` и адрес сервера с доступной моделью. Внутри контейнера `localhost` обозначает сам контейнер: используйте адрес, доступный из Docker-сети. Подробности — в [инструкции разработки](docs/development.md#llm).

Токены социальных сетей можно добавить позже. Без них интерфейс и API запускаются, но импорт данных из соответствующих сетей недоступен. Геокодирование, почта и мониторинг ошибок также настраиваются отдельно.

### 2. Запустите приложение

```bash
docker compose --env-file .env.docker up --build -d db migrations backend frontend
docker compose --env-file .env.docker logs -f backend
```

PostgreSQL сохраняет данные в Docker volume. Сервис `migrations` применяет миграции перед запуском API. Первая сборка требует доступа к реестрам Docker, PyPI и npm.

| Адрес | Назначение |
| --- | --- |
| <http://localhost:5173> | Веб-интерфейс |
| <http://localhost:8000/docs> | Swagger / документация API |
| <http://localhost:8000/health/live> | Проверка процесса API |
| <http://localhost:8000/health/ready> | Проверка БД и наличия применённой миграции |

Для первого входа зарегистрируйтесь через интерфейс. В режиме `dev`, если SMTP не настроен, код подтверждения выводится в журнал backend. При регистрации создаётся организация, а её первый пользователь получает роль администратора этой организации.

Остановить сервисы, сохранив базу:

```bash
docker compose --env-file .env.docker down
```

## Запуск без Docker и разработка

Подготовка Python и Node.js, миграции, тесты, настройки модели и сборка интерфейса описаны в [docs/development.md](docs/development.md).

Основные настройки хранятся в двух шаблонах:

- [`.env.example`](.env.example) — БД, авторизация, LLM, социальные сети и серверные интеграции;
- [`frontend/.env.example`](frontend/.env.example) — адрес API и публичные настройки интерфейса.

Значения `VITE_*` доступны в браузере: храните там только публичные параметры, а серверные токены — в `.env` или `.env.docker`.

Для Telegram нужна пользовательская MTProto-сессия. Ограничения импорта и настройка прокси описаны в [docs/telegram.md](docs/telegram.md).

## Структура проекта

```text
backend/
  app/                    # FastAPI, конфигурация, жизненный цикл и мониторинг
  db/                     # Модели SQLAlchemy и подключение к БД
  modules/                # Аналитика, соцсети, контент, отчёты, организации, авторизация
frontend/
  src/                    # Страницы, компоненты и клиент API
  tests/                  # Браузерные тесты Playwright
alembic/                  # История миграций базы данных
tests/                    # Модульные и интеграционные тесты backend
tools/                    # Импорт, диагностика, бэкапы и оценка качества
data/                     # Поставляемые справочники и локальные кеши
docs/                     # Инструкции разработки и интеграций
llm_comments_analytics/   # Скрипты оценки классификации комментариев пабликов
```

Исследовательские скрипты не входят в запуск приложения; для них могут потребоваться отдельные датасеты и дополнительные зависимости.

## Развёртывание и публикация

`docker-compose.yml` предназначен для локальной разработки. `docker-compose-prod.yml` и `.gitlab-ci.yml` описывают отдельное серверное окружение с частным реестром образов и внешней Docker-сетью; перед использованием их нужно адаптировать под свою инфраструктуру. Подробнее — [развёртывание](docs/development.md#развёртывание).

Перед первым коммитом воспользуйтесь [инструкцией публикации](docs/publishing.md). Локальные настройки, сессии Telegram, дампы БД, отчёты и результаты экспериментов исключены через `.gitignore`.

Лицензия проекта в корне репозитория пока не определена. Поле `license` в пакете frontend не заменяет лицензию на весь проект.
