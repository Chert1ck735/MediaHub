# Подготовка к публикации

## Состав репозитория

В Git должны попасть исходники, миграции, тесты, инструкции, lock-файл npm и шаблоны `.env.example`.

`.gitignore` исключает:

- реальные `.env`, `.env.docker`, `.env.frontend` и `frontend/.env`;
- сессии Telegram, файлы ключей и локальные настройки инструментов;
- дампы БД, бэкапы, выгрузки, отчёты, кеши, веса моделей и результаты MLflow;
- служебные файлы старой серверной поставки (`REMOVED_FILES.txt`, `before.json`, `g.py` и пустой текстовый документ).

Эти файлы сохраняются локально. Справочники `data/object_directory.json` и `data/settlement_municipality.json`, исходный код `frontend/src/lib/` и оба шаблона `.env.example` должны оставаться в репозитории.

Правила `.gitignore` не исключают уже отслеживаемые файлы. В существующем репозитории проверьте их через `git ls-files`; при необходимости уберите конкретный локальный файл из индекса командой `git rm --cached -- путь`, сохранив его на диске.

## Первый коммит

Если папка ещё не является Git-репозиторием:

```bash
git init -b main
git add .
git status --short
git diff --cached --stat
git diff --cached --check
```

Перед коммитом просмотрите состав индекса и сам diff. В нём не должно быть реальных токенов, паролей, строк Telegram-сессий или пользовательских выгрузок. Публичные `VITE_*`-ключи доступны в браузере; на стороне провайдера настройте для них ограничения по доменам.

Проверьте применимость серверных `.gitlab-ci.yml` и `docker-compose-prod.yml` к вашему окружению. GitHub Actions проверяет backend и сборку frontend; GitLab-конфигурация содержит отдельный процесс сборки и развёртывания на исходном сервере.

После проверки можно сделать коммит:

```bash
git commit -m "Prepare SIGMA MediaHub for publication"
```

Затем подключите свой удалённый репозиторий через `git remote add origin <URL>` и выполните `git push -u origin main`. Адрес репозитория и доступ к нему задаются владельцем проекта.

## Лицензия

Перед публичным распространением определите лицензию и право публиковать исходники, встроенные шрифты, изображения и справочники. В корне проекта пока нет `LICENSE`; указанное в npm-пакете frontend значение `ISC` само по себе не определяет лицензию всей системы. Автоматически выбирать лицензию за владельца проекта нельзя.
